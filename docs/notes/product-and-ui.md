## Route pages: data lessons (live, main f27bfee)
- `scripts/routes.py` reads only Parquet + data/stats.json, never stops.json. stops.json drops trains whose planned times vary (reused numbers like ICE 2835), so pages built on it undercounted Hamburg-Berlin (51 of 242 trains). Pages = pairs of stations with >= MAJOR_RUNS runs, >= MIN_TRIPS measured, recent planned time >= MIN_MINUTES (35). Share counts every run; the train list shows only trains that ran regularly in the last 3 months, and `unlisted` says how many trips sit outside it (shown in the route.method note).
- DuckDB pitfall: `arg_max(a, seq)`, `arg_max(b, seq)` skip NULLs per column, so with a station listed twice in a run (Berlin tief/oben) they come from different rows and a cancelled stop looks punctual. Take the whole last row with `qualify row_number() over (partition by run, name order by seq desc) = 1`.
- Check any new route set against an independent query on the raw Parquet (different query shape) for ~10 pages incl. Hamburg-Berlin, Köln-Berlin, München-Nürnberg and Frankfurt Flughafen (station name differs from short name).
- Search opens a page only for the two main stations (`pageFor`: Köln Hbf, Berlin Hbf), never a different station of the same city.
- Build cost: 685 routes = 2,744 share images, `npm run build` 8.5 min locally, ~22 min on Vercel (limit 45). Images are palette-compressed through sharp (128 colours, ~30% size, no banding). A page deploy therefore takes ~10-22 min; poll the commit status in a background process with notify, not a foreground loop (foreground tool timeout is 420 s).
- /routes/ HTML is 775 kB raw (44 kB on the wire) because of the 'All routes' list; watch it if routes grow.
- Shell guard: an inline `python3 - <<EOF` after a long chain once failed the scan; put checks in a file. the editor on an existing file needs a full the editor first, else use patch.
- When a new table lands above an existing one on a page, scope test selectors to their section (`section[aria-labelledby=trains] table.tt`): a bare `table.tt` silently starts reading the new table.
- Dictionary files: EN files end `} as const;`, DE files end `};`. A script that inserts keys before `} as const;` silently skips every DE file; check-dict catches it. Insert before the file's actual closing line.
- Don't chain `kill <pid> && ... git push`: if the server already exited, kill fails and the push silently never runs. Kill on its own line, then verify `git ls-remote origin refs/heads/main` equals HEAD.
- Verify production with (local scratch) (all route URLs and images) plus the browser scripts flow.mjs, hamburg.mjs, sharebtn.mjs with BASE=https://german-punctuality.vercel.app.


## Voice search (branch voice-search, not live until ELEVENLABS_API_KEY is set on Vercel)
- Browser -> ElevenLabs Scribe v2 Realtime over a WebSocket (`lib/voice.ts`, no SDK; AudioWorklet resamples to 16 kHz PCM; server VAD commit after 1.1 s of silence). The key never reaches the browser: `api/scribe-token.js` (root Vercel Function, `vercel.json` pins fra1) mints a single-use token (15 min). POST needs a same-origin Origin header; GET answers whether the key is configured, and the mic button is hidden unless it is (so a static host or an unconfigured deploy shows no dead button).
- `lib/spoken.ts` turns a sentence into search text: cuts at to/nach/bis, keeps the station words next to the cut, understands spoken times (acht Uhr vierzehn, halb neun, half past eight in the evening). ## Connection odds (live on main)
- `scripts/connections.py` (~8 min, 1.5 GB, run in the background) writes data/connections.json (ladder per station and planned gap, loaded by the closed "typical change" guide on /change) and data/connection-pairs.json (per arriving train: per station, the next trains with outcomes; shipped to /search/connection-pairs.json and loaded by ChangeTrains). Both are committed like routes.json.
- Only count pairs somebody changes between: drop B that goes back to A's previous stop (same train turning round) or on to A's next stop (stay on board), and B = A. Without that, a planned 3-minute change at Hannover read 68%; the real figure is 46%.
- A change works at m minutes when actual departure of B minus actual arrival of A >= m; a cancelled B is a miss; a cancelled A is not counted. The per-train rows are dominated by how late the arriving train itself runs (ICE 1541 is late 57% of the time, so even a 17-minute planned change works only 25%): correct, but surprising; say so on the page if users ask.
- Verified against independent DuckDB queries (different query shape): 12 station-gap rows and 9 train-pair rows match exactly. Do the same after any change to the pairing rules.
- UX of the station ladder: station chips + remembered station (localStorage), whole ladder at once, one 'I need more time' toggle (2 vs 6 min); it now lives in the closed guide on /change (see Change trains v2) and train pages link into the flow.
- Tests: conn2.mjs (old suite, lost) (ladder guide, 30 checks), change-flow.mjs (old suite, lost) (train-to-train flow), voice-hidden.mjs (old suite, lost). German review changed 'ab ICE 1541' to 'vom ICE 1541', 'halten fuer' (wrong: means mistake for) to 'warten lassen', and avoids 'Verbindung' (DB app word for one journey).
- Voice is OFF unless VOICE_ENABLED=1 is set in Vercel (the user found the voice experience buggy). `api/scribe-token.js` answers GET with 200 {ok:false} when off so visitors' consoles stay clean; tests turn it on with TEST_VOICE=1 on serve-api.mjs (old suite, lost).
- Release check pitfall: the GitHub commit status of a SHA is shared with the branch preview of the same commit, so if the commit was pushed to a branch first it already says `success` when `main` is pushed, and the live checks hit the OLD site (voice still on, connections.json 404). Wait on the live site instead: poll a marker that only the new build has (e.g. GET /search/connections.json = 200, or the changed endpoint answer) before running prodcheck/conn.mjs/flow.mjs. A fast-forward deploy took ~2 min with the image cache warm.
- Design status: direction B ('printed timetable', light, Archivo) from gp-design/v1 is shipped; the UX flow audit is in (local design folder) The owner's rule for flows: a first-time visitor must never open the site and be confused; judge by entry point (shared card, search engine, home) and tap budget, not by looks.

Live bugs found: home example chip 'Köln Hbf' and 'Berlin'+Enter give 'Add the train number after KOLN/BERLIN' (EN+DE); live words ('today', 'Verspätung … heute') get no 'not live' notice; slow network shows 'No suggestions' while the index loads. ## Method that works
- Edit with small Python patch scripts written via the editor, then run them; one huge terminal heredoc was rejected once. the editor on an existing file needs a prior the editor.
- Long data jobs: background with notify; ignore stale completion notices from superseded runs.
- Verify numbers independently from raw Parquet before shipping; verify visuals by looking (an image check) AND measuring in the browser; state what was not verified.
